# 基本面榜单 · 共振逻辑说明

> 适用范围：`/market-scan`（共振扫描页）的「共振档位」模式与「叠加技术面」模式。
> 一句话：**基本面给「值不值得买」，技术面给「现在是不是买点」，两者各自独立打分，只用双阈值做分类，不合成第三个总分。**

涉及代码：

| 层 | 文件 |
| --- | --- |
| 共振内核（五维正交） | `backend/app/core/confluence.py` |
| 形态引擎（Nison 蜡烛） | `backend/app/core/pattern_engine.py` + `nison_patterns.py` / `pattern_strategies.py` / `rare_patterns.py` |
| 周线折叠与趋势 | `backend/app/core/timeframe.py`（`weekly_trend_at`） |
| 形态 × 共振取案（打分主入口） | `backend/app/services/market_confluence_service.py`（`_scan_job` / `_combined_score`） |
| 榜单读层 + 技术叠加 + 共振视图 | `backend/app/services/market_scan.py` |
| 接口 | `backend/app/api/v1/fundamentals.py` |
| 前端 | `frontend/src/views/MarketScanView.vue` |

## 1. 三层漏斗总览

```
第一层  基本面榜单（只读 factor_snapshots，不重算）
        composite_score = Σ(模块分×w)/Σw  → risk 限幅 → 各类 veto → 事件扣分
        ↓ 只做筛选/排序
第二层  K线买点信号（_detect_buy_signal：MA20/MA60 + 量比 + PEG）
        ↓
第三层  形态共振（PatternEngine bullish 形态 × evaluate_confluence 五维正交）
        ↓
        双阈值分类 → 核心持仓 / 买入候选 / 观察 / 淘汰
```

关键约束：**第二、三层不参与任何分数合成**。榜单的 `composite_score` 一律来自因子快照，
技术面只产出 `tech_score`（独立字段）与 `verdict`（分类标签）。

## 2. 第一层：基本面分从哪来

`market_scan.scan_market()`（`market_scan.py:376`）

1. `load_covered()` 直接读 `factor_snapshots`，按 `composite_score` 排序；
   因子库由盘后 `factor_db.build_all()` 预构建，内容即 `analyze_symbol_full()` 的结果。
2. 展示列 `market_pct` / `industry_pct` 是**横截面分位**，只用于定位，不参与排序；
   缺失值既不参与排名，也不赋中性 50 分。
3. 默认过滤：剔除 ST/退、默认仅沪深主板（`300/301/302/688/689` 需勾选才纳入）。
4. 排序可选 `composite_score` 或五维之一；**按维度排序只是展示排序，不合成新总分**。

覆盖率由 `market_coverage()` 自证（已覆盖 / SH·SZ 总数），接口随响应返回。

> 估值维度（`engine.py` 非红利路径）构成：`PE 历史分位 50% + 相对 PE 30% + 股息率 20%`，
> 成长股另有补充因子（毛利率 / 营收增速 / 动态 PE / PEG 核心锚）。
> 两项**有限度折减**（取 max，禁止叠加，上限 22 分）：
> ① 现金流质量 < 45 分且账面估值偏便宜；② **周期陷阱**（见 §13.3）。

## 3. 第三层：形态共振怎么算（核心）

入口 `MarketConfluenceService._scan_job()`（`market_confluence_service.py:352`），
`technical_overlay` 与共振索引都复用它，保证「信号页 / 榜单 / 共振视图」逐位同源。

### 3.1 取案流程

| 步骤 | 规则 | 位置 |
| --- | --- | --- |
| 取 K 线 | `KLINE_LIMIT = 90` 根；不足 `MIN_BARS = 40` → 跳过 | `:36-37` |
| 跑形态 | `PatternEngine(min_score=60).scan(candles)` | `:359` |
| 剔除西方工具形态 | `WESTERN_NOT_CANDLES`（黄金交叉/死亡交叉）不当形态触发 | `:369` |
| 只留看涨 | `r.direction == "bullish"` 才继续 | `:372` |
| 只看近期 | `candle_index` 必须落在最近 `recent_bars = 2` 根内 | `:363-375` |
| 共振门槛 | `evaluate_confluence(...)` 后要求 `conf.ok` | `:376-378` |
| 候选门槛 | `_is_candidate(...)`：无 `emotion_extreme` / `structure_flaw` 软冲突，且组合分 ≥ 80 | `:75-79` |
| 取最优 | 取组合分最高的那一条形态 | `:382-402` |

### 3.2 技术面得分公式

```
组合分 combined = 形态分 + 有效共振数 × 6 − 8 × (low_momentum 软冲突条数)
技术面得分 tech_score = min(round(combined), 100)      # 只截顶，不重标定
```

- `形态分`：PatternEngine 命中的 Nison 蜡烛形态置信度（0~100，门槛 60）。
- `有效共振数`：五维正交后各维度保留项的**权重之和**（`effective_count`）。
- `CANDIDATE_COMBINED = 80`：组合分低于 80 直接不入选。

**由此推出一个反直觉但重要的性质**：能给出 `tech_score` 的票，其组合分必然 ≥ 80，
所以只要「有达标形态共振」，技术分天然 ≥ 80。
这正是 `min_tech = 70` 在本数据集上等价于「有形态共振」的原因——**真正的区分线是 85**。

无达标形态共振 → `tech_score = None`（不可评估），**不赋 0、不赋中性 50**。

### 3.3 五维正交（`confluence.py`）

命中项按维度归并，同一维度只保留 `(权重, 优先级)` 最大的一项（`finalize()` `:192`）：
一维一项，避免「均线支撑 + 均线转多 + 金叉」三连刷同一维度。

| 维度 | 归入的命中项 |
| --- | --- |
| trend | 周线趋势、均线转多/转空、金叉/死叉、上升/下降趋势线 |
| momentum | MACD、RSI、随机指标、RSI 背离、MACD 背离 |
| volatility | 布林、波动率拐点 |
| volume | 放量、缩量回撤 |
| structure | 均线支撑/阻力、低点/高点、窗口支撑/阻力、极性支撑/阻力、回撤支撑/阻力、形态互证 |

`effective_count = Σ weight`，且 `conf.ok` 要求 `effective_count ≥ MIN_HITS = 2.0`（双证）。

### 3.4 硬冲突（一票否决）

| 触发 | 结果 |
| --- | --- |
| 周线向下 + 看涨形态（或周线向上 + 看跌） | 硬冲突，`blocked`（尼森：先看周线） |
| 看涨且 RSI ≥ 85、贴 20 日高点、MACD 柱仍升 | 极端超买硬否决 |
| 看跌对称条件（RSI ≤ 15） | 极端超卖硬否决 |

周线趋势判定：日线折叠成 ISO 周线（`to_weekly`），≥10 根周线后用
`is_uptrend`（更高的高点 + 更高的低点）/ `is_downtrend` 判定，否则 `sideways`（`timeframe.py:149`）。

### 3.5 软冲突（三类，均可拦候选）

**`structure_flaw`（结构缺陷）** — 一旦出现，`_is_candidate` 直接判否：

- 上影刺破 MA20 但收盘未站上（按收盘价不算突破）；
- 上影刺破前高但收盘未越过；
- **日线均线空头排列 `MA5 < MA10 < MA20` 时给看涨形态** → 「逆短线趋势，等待放量站回 MA20 再确认」（`:494`）；
  （对称地，多头排列时拦截看跌形态。）
- **左侧超跌形态防守**（2026-09-21 第四轮，第五轮改为**决策日口径**）：形态名 ∈ `LEFT_SIDE_BULLISH`
  （平底锅底部 / 破低反涨 / 看涨吞没 / 启明星 / 刺透 / 锤子线 / 平头底部 / 藏婴吞没 等 17 个）
  **且** **决策日**收盘 < MA60 **且** **决策日**量比（当日量 ÷ 前 20 日均量）< `VOL_CONFIRM_MIN = 1.2`
  → 「左侧超跌形态：…中期趋势仍向下，等待放量站上 MA60 再确认」。
  三个条件全满足才拦：在 MA60 上方、或决策日放量者一律放行。

> **决策日 vs 形态日**（第五轮修正，务必分清）：
> 闸门判定的是 `decision_index`（扫描层传 `len(klines)-1`，即最新一根 K 线），
> **不是**形态发生那根。理由：榜单/信号页回答的是「**今天**能不能买」，用户看到的
> 也是今天的价与量；而形态日通常自带放量（平底锅底部往往伴随一根量柱），
> 按形态日判定等于闸门永不触发 —— 见 §14。不传 `decision_index` 时退回形态日口径
> （历史调用方与单测行为不变）。

**`emotion_extreme`（情绪极端）** — 同样直接判否：

- 随机指标 `%K ≥ 90` 超买（附带仓位 ×0.7、扣 8 分）；
- 收盘贴 20 日高点 + RSI ≥ 72 + MACD 柱仍未回落 → 高位追涨。

**`low_momentum`（动能不足）** — 不判否，但组合分 −8：

- 量能约均量 1.2~1.5 倍（突破确认偏弱）；
- 缩量反弹：收阳但量 < 均量 0.78 且环比继续缩。

> 左侧防守为什么与「空头排列」并列而不是新造一类：
> 空头排列拦的是 `MA5<MA10<MA20`（短线也还在下行）；真实缺口是
> **`MA5` 已上翘、但价格仍在 MA60 下方** —— 下跌途中的反弹刚起步，
> 形态分能打满，共振却是「无量 + 中期趋势向下」。线上实测（2026-09-21）：
> 北方华创 收 676.61 / MA60 724.61、量比 0.87；雅克科技 收 137.43 / MA60 153.37、
> 量比 0.97；平安电工 收 88.15 / MA60 91.96、量比 0.78 —— 三只都靠「平底锅底部」
> 拿到 `combined = 105` 并入选。二者处置强度相同（都是 `structure_flaw`），
> 不额外叠加惩罚。

### 3.6 命中项的具体门槛（节选）

| 命中项 | 触发条件 |
| --- | --- |
| 均线支撑 | 看涨且收盘 ≥ MA20×0.985（或当日上穿 MA20），且无上影假突破 |
| 均线转多 | `MA5 ≥ MA10`（需同时存在 MA20） |
| 金叉 | 近 6 根内出现均线黄金交叉；权重按新鲜度 `T+0=1.0 / T-1~3=0.8 / T-4~5=0.5` |
| 周线趋势 | 周线波段向上（看涨）/ 向下（看跌） |
| MACD | **要求 DIF 已在 DEA 正确一侧**；「绿柱缩短」不算转多 |
| RSI | 看涨要求 `28 ≤ RSI ≤ 60`（**45~60 满权 1.0，28~45 降权 0.6**）；看跌对称 `40 ≤ RSI ≤ 72`。超卖（<28）仍不算做多证据 |
| 随机指标 | 看涨要求 `%K > %D` 且 `%K < 40`（已金叉的低位）；超卖本身不算证据 |
| RSI/MACD 背离 | 价格创新低（高）而指标未创新低（高） |
| 放量 | 量 ≥ 均量 × (1.5×k)，k 随近 20 日量能波动率自适应；否则落在 (1.2×k, 1.5×k) 转 low_momentum |
| 缩量回撤 | 前 3 日至少 2 日缩量 < 均量 0.85，今日量回升且收阳/收阴配合 |
| 低点/高点 | 收盘距 20 日低点（高点）≤ 3% |
| 布林 | 贴下轨 / 站上中轨（看涨方向） |
| 波动率拐点 | 带宽收窄后扩张或 ATR 压缩后抬升，且触轨 |
| 窗口支撑/阻力 | 未回补的跳空窗口（仅收盘填补才算失效） |
| 极性支撑/阻力 | 前高转支撑等极性位回测（±1.5%） |
| 趋势线 / 回撤 | 趋势线邻近、百分比回撤位命中 |

## 4. 第二层：K 线买点信号

`_detect_buy_signal()`（`market_confluence_service.py:135`），**是决策的下游**，
不参与 `tech_score`：

| 信号 | 条件 |
| --- | --- |
| 左侧超跌观察 `left_side` | **优先级最高**。技术面已被左侧防守否决（`left_side_blocked`），或形态达标但未站上 MA20 / 量能未放大 |
| 强买入 `strong_buy` | 基本面 ≥ 80 且 PEG < 1.5 且 站上 MA20 且 近 5 日均量较 20 日均量放大 > 20% |
| 观察 `watch` | 基本面 ≥ 80 且 PEG > 2 且 回踩 MA60（±3%）且 缩量 > 10% |
| 短线博弈 `short_term` | 基本面 < 60 且 突破 MA20 且 放量 > 20% |
| 右侧底部企稳 `bottom_confirm` | 左侧形态 + 站上 MA20 + 放量（趋势已由均线确认） |
| 形态达标待确认 `setup_ready` | 通过候选门槛，但形态属延续类（红三兵 / 上升三法 / 升窗回测…），等回踩或放量突破 |
| 趋势未确认 `neutral` | 无形态共振，且未触发上面任何一条 |
| 数据不足 `insufficient_data` | K 线 < 60 根 |

**买点信号是决策的下游，不允许与决策互相打脸。** 凡通过形态共振候选门槛的票，
信号至少落到 `setup_ready`——不会出现「决策=买入候选 / 买点=中性」；
技术面被左侧防守否决的票，信号必须是 `left_side` 而不能是 `strong_buy`。

`PEG` 取个股分析已算好的值（`engine._growth_for_peg`，见 §12.2），
`None` → 强买入/观察档保守不触发（不在榜单侧另算第二个 PEG）。

## 5. 决策：双阈值分类（`_verdict` `market_scan.py:561`）

判定顺序（先淘汰，再核心，再候选）：

```
1. 基本面 < veto(60)  或  技术面 < veto(60)        → 淘汰
2. 基本面 ≥ 85  且  技术面 ≥ 85                    → 核心持仓
3. 基本面 ≥ 70  且  技术面 ≥ 70                    → 买入候选
4. 其余                                            → 观察
```

- **缺失不当作最差**：技术面 `None`（无达标形态共振）归入「观察」并给出原因，不按 < 60 淘汰。
  若 `None` 来自**左侧超跌形态防守**（`tech_blocker` 非空），理由文案改为
  「技术面已否决：左侧超跌形态…」——「形态有、但不让买」与「本来就没有形态」
  对用户是两条不同的信息，不能共用一句「无形态共振」。
- 四个阈值均可由请求参数覆盖（`min_fund` / `min_tech` / `core_score` / `veto_score`）。
- `verdict` 只是标签：`composite_score` 与技术面原始读数一律**不改写**。

**排序**（共振视图 `resonance_view` `:982`）：

```
档位优先（核心持仓 → 买入候选 → 观察 → 淘汰）
  → 同档按 tech_score 降序（缺失排最后）
    → 再按 composite_score 降序
```

「仅看某档」= 服务端过滤（`verdict_filter`：`core` / `candidate_up` / `eliminated`）；
「仅看有信号/共振」= 前端 `hasSignal()` 按 `buy_signal` 的 6 个阶段标签（或 `pattern_name`）过滤。

## 6. 两种用法与缓存

| | 叠加技术面（普通榜单） | 共振档位（默认模式） |
| --- | --- | --- |
| 接口 | `GET /fundamentals/market-scan/technical-overlay` | `GET /fundamentals/market-scan/resonance` |
| 排序 | 仍按基本面（综合分/维度） | 按共振档位全局排序 |
| 覆盖 | **本页全部标的**（不按名次截断） | 全榜单存量 |
| 成本 | 随翻页增量计算 | 后台索引一次构建，读层毫秒级 |
| 索引 | 无需 | `POST .../resonance/build` + `/progress` 轮询 |

缓存与容错：

- 单票技术结果缓存 10 分钟（`OVERLAY_CACHE_TTL_SEC`）；翻页只算新出现的票。
- **分析失败不写缓存**，并发失败后串行重试一次（多为盘后批跑的 SQLite 写锁竞争）；仍失败则如实显示「分析失败」。
- 共振索引只对 `composite_score ≥ 60` 的标的算技术面（更低者按规则直接淘汰，无需技术面）；
  索引 10 分钟内复用，过期重建只重算真正过期的票。若把淘汰线放宽到 60 以下，缺失技术面的票按「观察」处理，不会误淘汰。
- 索引构建期间页面显示进度；索引未构建时接口返回 `{"empty": true}`，前端自动触发构建。

## 7. 与信号页的同源与差异（重要）

同源：`combined = 形态分 + 有效共振数 × 6`、`low_momentum −8` 完全一致
（`signal_service.py:311`）。

差异一处：软冲突的**处理力度**不同。

| 软冲突 | 信号页（`_level_from_confluence`） | 榜单（`_is_candidate`） |
| --- | --- | --- |
| `emotion_extreme` | strong 封顶为 medium（仍出信号） | **直接剔除，无技术分** |
| `structure_flaw` | strong 封顶为 medium（仍出信号） | **直接剔除，无技术分** |
| `low_momentum` | 组合分 −8 | 组合分 −8（一致） |

即榜单口径比信号页更严：榜单要的是「有共振且无结构瑕疵」的标的，
信号页允许带瑕疵但降级出信号。

## 8. 口径边界（自证与已知限制）

明确**不纳入**技术面得分的项：

- **大盘环境**：无取数链路，不做指数择时。
- **个股资金面**：主力资金/融资融券/龙虎榜虽已具备取数能力，但**不在 `tech_score` 内**，
  仅在个股报告与「技术面成文分析」中展示，避免造第二套技术面权重表。

已知限制：

1. **K 线覆盖**：`kline_data` 只收沪深主板非 ST（约 3078 只），创业板/科创板/ST 会恒显「K线不足40根」。
2. **周线窗口**（2026-09-21 已修复）：`KLINE_LIMIT` 由 90 提到 180（≈36 根周线），
   周线硬否决恢复效力；同时与「技术面成文分析」同窗口，消除同一只票周线趋势两处不一致的隐患。
3. **「跌得深」不算利好**：贴 20 日低点/贴布林下轨仍会被 structure / volatility 维度命中，
   由空头排列守卫（3.5）拦截，不是独立否决。
4. **覆盖率渐进**：因子快照覆盖率由构建预算决定，榜单只在已覆盖样本内成立，页面显式给出覆盖率与分位基准。

## 10. 口径调优记录（2026-09-21 第二轮）

针对「RSI 区间偏窄 / 周线窗口过短 / 放量阈值偏高 / 缺大盘环境 / PEG 对周期股失真」

| # | 意见 | 结论 | 落地参数 |
| --- | --- | --- | --- |
| 1 | RSI 区间放宽到 25~55 | **部分采纳**（上界放宽、下界不动、加权重分档） | 看涨 `28~60`，看跌 `40~72`；中轴区满权，弱势区 0.6 |

### 10.1 为什么 RSI 下界不放到 25

`RSI < 28` 是超卖区。2026-09-21 第一轮修复的核心结论就是「超卖 ≠ 反转」——
002545 的 RSI 18 曾被当成做多证据，正是那次误判的根因。反转证据走「RSI 背离」，
不能靠放宽下界找回来。

上界从 48 放到 60 是为了接住**强势股回调不破 50~60** 那一段；同时给 28~45 / 55~72
这两个「动能未确认区」降权到 0.6——0.6 + 另一维 1.0 = 1.6 < `MIN_HITS`(2.0)，
所以弱势区的 RSI 撑不起双证，只是「擦边加分」，不会造成组合分无条件通胀。

### 10.2 量能动态阈值的方向

`CV`（近 20 日量能变异系数，不含今日）衡量「量能基线本身有多不稳」：

- 量能平稳的缩量行情（CV 小 → k < 1）：1.3~1.4 倍已是有效突破，阈值下调；
- 量能忽大忽小的票（CV 大 → k > 1）：1.3 倍很常见，阈值上调，且**不再罚 low_momentum**；
- CV 不可得（不足 10 根基线）→ k = 1.0，退回原固定阈值 1.5× / 1.2×。

命中文案带自证：`确认放量 1.2万≈均量 1.34 倍（阈值 1.28×，动态阈值基于量能波动 CV=0.21）`。

### 10.3 大盘环境为什么坚持不入分

意见本身也认可「不一定纳入 tech_score」。系统不自动改门槛，理由有三：

1. 项目铁律：不得新造第二套权重、同一判定不两处各算；
2. 自动降门槛会让「历史榜单」与「今日榜单」在同样的个股形态下给出不同档位，无法复核；
3. 指数状态是**外部条件**，把它揉进个股技术分后，用户无法分辨「这只票弱」还是「大盘弱」。

因此实现为：后端给指数读数与判定规则，前端给一句建议 + 一个「按提示把技术面门槛提到 85」
按钮 —— 点了才生效，且表单上能改回来。

### 10.4 第 5 条的真问题不是缺 PB-ROE

核实代码后发现两套 PEG 并存：

| 位置 | 算法 | 周期股 |
| --- | --- | --- |
| 个股分析 `engine._growth_for_peg` → `relative.PEG` | 3 年净利 CAGR 优先 | 负 CAGR 置 `None` 并附 note（周期底部） |
| 榜单买点信号 `market_confluence_service._calc_peg` | `PE_TTM ÷ 单期净利同比` | **无任何豁免** |

后果：煤炭/钢铁在景气高点（低 PE + 单期同比 400%+）会被算出 PEG 0.07，
在榜单里被标成「PEG<1.5 估值合理 → 强买入」——这正是意见里担心的失真，
但根因是口径分叉，不是缺少 PB-ROE。

修法是让扫描层**直接复用 `relative.PEG.value`**（快照里 engine 已算好、已豁免），
`_calc_peg` 保留仅供旧调用与诊断。这样 PEG 只有一个来源，周期股自动继承既有的
「负 CAGR → 不适用 PEG」判定，既不需要引入 PB-ROE 新框架，也不会产生第二个 PEG。

## 12. 口径复核：外部质疑第一组（2026-09-21 第三轮）

外部意见提出「三个核心漏洞」。逐条复核结论：**证据多与事实不符，但暴露了 3 处真实缺陷**。
下面只记录经代码/线上数据证实的部分。

### 12.1 「基本面风控（Veto）未生效」→ 部分成立，但根因不是「没有估值红线」

指认样本 600722 金牛化工（PE 193.5 / PB 8.49 / 股息率 0.5%，综合分 71.5）。
复核后的事实：

- 它**不是**「基本面极差股」：偿债 93.9、现金流 75.8 分是真的（详见 §12.3 的分位数据）；
  真正异常的是 ROE 4.39% 配 PB 8.49 —— 利润率极薄但资产端被炒到 8.5 倍净资产。
- 外部提出的 `PE_TTM > 80 → composite = 0` **不予采纳**：一刀切会误杀
  北方华创（PE 86，半导体设备真成长）。绝对 PE 门槛在 A 股没有普适性。
- 真实缺陷是**估值分对 PE 不单调**：

  | PE_TTM 区间 | 估值维度得分 |
  | --- | --- |
  | 10~20 | 73 |
  | 40~80 | 37 |
  | **80~150** | **52.3** |
  | 150+ | 46 |

  PE 超过 80 之后分数**反弹**，因为 `growth_profile.classify_growth_stock` 里有一条
  自证循环：`pe_ttm > 80 且未判成长 → 判为成长 → 走成长股估值框架 → PE/PB 极端值软化`。
  实测覆盖率 **1068 / 1076 = 99.3%** 的 PE>80 股票都走了这条路，
  `pe_distorted` 档估值中位 41.0，反而高于普通股（28.0）。
  **已修**：删除 `pe_distorted` 自证规则（见 `growth_profile.py`）。

### 12.2 「买点信号全是中性」→ 成立，但根因是 PEG 取数路径写错

外部把原因归为「形态共振与买点信号割裂」。复核后：**真正的根因是一个静默 bug**。

`market_scan._snapshot_peg_map` 读 `$.relative.PEG.value`，
`market_confluence_service._extract_fundamental_fields` 读 `result.get("relative")` ——
但快照 payload 与 engine 返回 dict **都没有顶层 `relative`**，相对估值块整体挂在 `valuation` 下
（真实路径 `$.valuation.relative.PEG.value`）。结果**全库 PEG 恒为 None**，
而 `strong_buy` / `watch` 两档都硬性要求 `peg is not None` —— 整张榜单买点信号
100% 落在 `neutral`，档位静默失效且无任何报错。

更要命的是：**旧用例手搓了顶层 `relative` 的 fixture**，把错误路径固化成了「期望」，
于是生产环境失灵而测试全绿。已修三处：

1. `_snapshot_peg_map` SQL 路径改为 `$.valuation.relative.PEG.value`；
2. `_extract_fundamental_fields` 改为 `(valuation.relative) or relative`；
3. **测试夹具改为按真实嵌套结构构造**，并新增 sqlite 端到端用例
   （`test_snapshot_peg_map_reads_nested_path_end_to_end`）防回归。

修复后线上实测：6 只抽样票 **5 只取到 PEG**（修复前恒为 0/6）。

外部的「`tech_score` 压制到 60 以下」建议**不采纳**：`tech_score` 上限是 100
（`min(combined, 100)`），外部误把它当成了形态分（75）。而空头排列的处置早已是
更彻底的 `tech_score = None`（不可评估），不是「压到 60」。

### 12.3 「估值与成长背离」→ 证据不成立，但缺口真实

指认样本 603995 甬金股份（PE 15.7 / PB 1.6 / 股息率 3.1% / 成长分 84.3）。
复核：甬金 2026Q2 归母**环比 +85%**（2024Q3 以来最高），毛利率在修复 ——
这是**周期修复**，不是外部所说的「景气顶点」。外部把「低 PE 就是周期高点」当成了定论。

真实缺口是 `cyclical_profile.py` 是**死代码（从未被 import）**，
而「周期底部反转」这条成长口径**没有任何估值前提** —— 只要 3 年 CAGR 为负 +

必然是「买入候选 + 中性」。

### 14.2 修正：闸门改按「决策日」判定

`evaluate_confluence()` 新增 `decision_index` 参数：

```python
def evaluate_confluence(klines, index, direction,
                        pattern_name=None, decision_index=None)
```

- 左侧超跌形态防守一律按 `decision_index` 取 **收盘 / MA60 / 量比**；
- 扫描层（`MarketConfluenceService._scan_job`）传 `decision_index=len(klines)-1`；

为什么必须是决策日：榜单/信号回答的是「**今天**能不能买」，用户看到的也是今天的
价与量。形态日放量只证明「那天有人买」，不证明「今天还站得住」——
09-18 放量、09-21 缩量回落，正是下跌中继的标准形态。

`pattern_name` + `decision_index=n`：改前它没传 `pattern_name`，闸门整体被跳过，
叙述里永远不会出现「左侧超跌」的**原因**说明。

**明确不覆盖的两个面**（口径不同，不是漏改）：
`signal_service` 的信号流水按「形态发生日」评估 —— 那是历史记录，
重新用今天的价去改写一条 09-18 已生成的信号等于篡改历史；
`backtest_service` 回测同理（且它不传 `pattern_name`，闸门自动跳过）。

## 16. 第七轮：分类准入闸门修两个洞（2026-09-22，scoring_version .5 → .6）

`.5` 部署后重新触发共振索引构建（`status:done / pct:100 / error:null`，`float(None)` bug 确认修好），
但**线上榜单核验**发现闸门有两个洞，其中一个正是用户最初投诉的金牛化工本体。

### 16.1 洞一：周期型曾是免检通道（严重）

`classify_admission_gate` 的周期分支只判 `cycle_trap`，而该参数在唯一调用点
（`_base_items`）**硬编码 `cycle_trap=False`**，注释写「见 `_overlay` 层补充」但 `_overlay`
从未补充 → **894 只强周期股全部无条件放行**。

实测混入 **143 只「PE分位≥80 且 ROE<6」**，与金牛化工同病：

| 标的 | 行业 | PE分位 | ROE |
|---|---|---|---|
| 泸天化 | 农化制品 | 99.3 | 0.50 |
| 招商蛇口 | 房地产开发 | 100.0 | 0.73 |
| 华菱钢铁 | 普钢 | 99.2 | 4.77 |
| 山西焦煤 | 煤炭开采 | 95.9 | 3.33 |
| **金牛化工** | **化学原料** | **89.8** | **3.92** |

**修复**：周期分支补「估值↔盈利矛盾」判据（PE分位≥80 且 ROE<6 → 拦），与传统价值型同尺。
**但仍保留豁免**：PE 处低分位时 ROE 为负照常放行——那正是周期底部该买的时点；
峰值周期股（中国神华 95.6 / ROE 12.76）也不受影响。

### 16.2 洞二：周转率兜底误杀整个金融业

兜底判据 `总资产周转率 < 0.15` 用制造业尺子量金融，实测误杀
**42 家银行 + 49 家券商 + 20 家多元金融**共 115 只：宁波银行 0.02、华泰证券 0.033、
华夏银行 0.019、苏州银行 0.016。银行赚息差、券商赚佣金，总资产周转率天然 0.02~0.08，
**不是低效而是业务模型**——这也与「红利型不看 ROE 和周转率」的原则一致。

**修复**：新增 `ADMISSION_FINANCIAL_INDUSTRY_KW`（银行/保险/证券/多元金融/信托/期货）
结构性豁免周转兜底；**豁免 ≠ 免检**，金融股仍过「矛盾组合」那一关
（宁波银行 ROE 11 → 放行；ROE 0.7 且 PE分位 100 → 照拦）。

`classify_admission_gate` 签名新增 `industry` 参数，闸门调用点传行业名。
注意 `_item_passes` 筛选里的 `industry=ind_filter` 与闸门无关，勿混。
