## 商络电子（300975）基本面分析系统错误修复

用户以商络电子 2026 中报为样本，审计出基本面分析系统的 5 处数据错误 + 4 项方法论缺陷，逐项修复并回归测试。

### 修复清单（文件 → 问题 → 方案）

1. **`analysis/financials.py` — 净利同比 300% 硬截断**
   - 原逻辑：`abs(profit_yoy) > 300` 时直接改写 `profit_yoy` 本身为 300，导致 2026 中报 493.25% 被显示成 300%，且 PEG/前瞻成长性都建立在错误分母上。
   - 方案：新增 `normalize_profit_yoy()`，拆成两个口径——`profit_yoy` 原样保留真实披露值（展示/评分/风险提示用），`profit_yoy_forward` 才是 ±300% 折减后的外推口径，另存 `profit_yoy_extreme` 标记。

2. **`analysis/modules/cashflow.py` — 自由现金流负值单位爆炸**
   - 原逻辑：`fcf / 1e8 if fcf > 1e6 else fcf` 用 `>` 而非 `abs()`，负值（-11.19亿）不换算，输出「-1119194300亿」。
   - 方案：改按绝对值判断量级；另新增 `_fmt_yi()` 自适应精度（10 亿以下保留 1 位小数），修掉「0.45亿分红显示成 0亿」的同类问题。

3. **`analysis/financials.py` — 资产负债率滞后于最新报告期**
   - 原逻辑：只在年报序列 `fd.index` 里回退选取，2026 中报已披露仍用 2025 年报 72.96%。
   - 方案：优先采用最新报告期资产负债表（非 1231 结尾时先试 `_pick_bs(latest_ymd)`），并记录 `debt_ratio_period` / `debt_ratio_scope`。实测已取到 75.76%（2026中报）。

4. **`analysis/financials.py` — 经营现金流/净利润口径不一致**
   - 原逻辑：用 `每股经营现金流/每股收益` 估算，两个每股指标各自四舍五入导致 ~2pct 偏差。
   - 方案：改用同报告期绝对值 `经营现金流 / 归母净利`（`sina_is_all[latest_ymd]['parent_net_profit']`），保留每股口径作兜底，并记录 `latest_cash_ratio_source`。实测 -289.7%。

5. **`analysis/engine.py` — 前瞻外推口径统一**
   - `_growth_for_peg()` 的回退分支、`_growth_rate()` 均改为优先取 `profit_yoy_forward`，避免 493% 把 PEG 压到 0.05 这种失真信号。

6. **`analysis/modules/growth.py` + `config/company_profiles.py` — 并购并表因子**
   - 新增「并购并表调整因子」指标，按公司画像（`merger_targets`）标注并表贡献，明确「非纯有机增长」，中性计分待公司披露有机口径后校准。商络电子画像：广州立功电子科技有限公司（2026 起纳入合并）。

7. **`analysis/modules/profitability.py` — ROIC/WACC 一票否决改造**
   - 原逻辑：单期 ROIC < WACC 直接判「毁灭股东价值」并在引擎层锁定估值分 ≤28。
   - 方案：新增 `business_model="distribution"` 认知（低净利率高周转）；计算 `roic_3y_avg` 归一化 ROIC；WACC 分层（分销 10.0%，有息负债率优先于含应付的资产负债率）；分销模式下 `roic_below_wacc=False`，且 ROIC 注释展示单期+3年均值双口径。

8. **`analysis/models/comps.py` — 可比公司商业模式错配**
   - 原逻辑：只按东财「所处行业」字符串选同业，分销商被拿去和法拉电子/顺络电子等被动元件制造商比。
   - 方案：新增 `peers_for(name, symbol, industry)` 显式同业清单，优先于行业自动筛选；返回 `peer_source` 标注来源；对目标自身做防御性排除。

### 关键项目约定（后续改动请遵守）

- **绝不改写真实披露值**：展示字段保持原始精度，任何折减/抑制只体现在独立的 forward 字段上。
- **金额单位统一走 `_fmt_yi()`**：禁止对「亿」级金额用 `:.0f`（小值会被舍成 0）。
- **「以最新报告期为锚」**：中报/季报已披露时，资产负债表与现金流比率都必须取最新报告期，不得回退年报。
- **单一比率不做一票否决**：ROIC/WACC、现金流等判定需带商业模式认知（`is_distribution`）与多期归一化。
- **可比公司优先用显式同业清单**，行业字符串仅作兜底。

## 深圳华强（000062）14.4 分 E 级 —— 评分链路的复合放大修复

用户反馈 14.4 分 E 级过重，判断应为 C+~B-，并给出了一份代码改造方案。**实测复现了 14.4 分，但真正的成因与用户的诊断不同**，且用户给的函数签名与现有架构不符（不能直接照搬）。

### 14.4 分的真实成因（逐层复算）

`composite = 32.75 × 0.44 = 14.4`，四层惩罚叠加，其中两层用户完全没提到：

| 层 | 机制 | 影响 |
|---|---|---|
| 1 | `MODULE_WEIGHTS` 里 cashflow 权重 0.32 = 其他维度 2 倍 | 已存在 |
| 2 | `E_GRADE_PENALTY = 0.5`：盈利 38.5、现金流 34.4、估值 28 均 < 40 → 贡献减半（44.3 → 32.7） | **用户未提，第二大杠杆** |
| 3 | `composite *= risk.score/100`：risk=44 → ×0.44（32.7 → 14.4） | **用户未提，最大杠杆** |
| 4 | 价值陷阱一票否决：letter 已是 E → 估值 base 60 锁定为 28 | 用户提到了 |

另外 user 说「PEG 0.59 未体现」是对的，但原因不是「被 E 级禁用」：PEG 确实算出了 0.59，只是估值模块自己的 `classify_growth_stock` 判 `is_growth=False`（漏传 V 型拐点标记），所以第 908 行的成长股分支没执行，PEG 核心锚/动态PE 都没进构成。而引擎后文用更全的输入又判它是 `turnaround` 成长股 —— 两处结论互相矛盾。

### 修复清单

1. **`config/company_profiles.py`**：新增 `_norm_code()` 归一化代码（`000062.SZ`/`SZ000062`/`000062` 等价）；`business_model_of()` 增加「显式分销同业名单即认定分销」；`peers_for()` 同步并排除自身。一次覆盖深圳华强/中电港/好上好/英唐智控/力源信息/香农芯创/润欣科技/雅创电子。
2. **`analysis/engine.py`（关键漏项）**：`ctx` 里**从来没传过 `symbol`**！各模块 `kwargs.get("symbol")` 一直拿到 None，所以只有带名称画像的公司（商络电子）能识别商业模式。补上 `"symbol": sym`。
3. **`analysis/engine.py`**：风险扣分限幅 `RISK_MAX_PENALTY = 0.25`（原为无上限乘法）。风险模块的扣分项（应收恶化/利润含金量低/存贷双高）在 cashflow、solvency 模块已各扣一次，再整体相乘属三重计数 + 复利放大。生存级风险仍由 `compliance_veto` 强制 E。
4. **`analysis/engine.py`**：估值模块复用成长模块的规范 `profit_cagr_3y` 与 V 型拐点标记（经 `meta["_growth_*"]` 传递），使 `is_growth` 判定与引擎一致，PEG 真正进入构成；并把「以 PEG/PS 为主」的文案改为仅在 PEG 确实进入构成时才输出。
5. **`analysis/modules/cashflow.py`**：修指标「名/值/分」三重错配。两个分支都按当期打分却沿用旧标签，导致 `name=(5年均值)` + `value=1.16` + `score=25(当期口径)` 自相矛盾。现在每个分支都把 `cr_label` 与 `score_ratio` 同步切到实际口径。
6. **`analysis/modules/profitability.py`**：毛利率改用分销口径阈值 `((12,100),(8,12),(4,8))` 替代制造业 `((50,100),(30,50),(15,30))`；同时把 `biz_model`/`is_dist_biz` 的计算**提前到毛利率打分之前**（原在 263 行才定义，直接在 162 行引用会 NameError）。

## 同业相对基准（分销/贸易）：深圳华强 55.4 C → 58.9 C

### 关键 bug：显式同业清单命中 0 家（上一轮自己引入的）

`select_comparables` 的显式清单路径，`_batch_quotes` 返回的 key 带交易所后缀（`001287.SZ`），
而清单传进来的是 6 位代码（`001287`），`_rank` 里 `quotes.get()` 全部落空 →
**peer_count 静默变成 0**，可比公司、PE/PB 分位、相对估值、signal 全失效

修复：清单保留原始写法作 key，改由 `_rank` 做多形式查找兜底
（`quotes.get(6位) or quotes.get(带后缀) or quotes.get(digits)`）。
实测 0 家 → 6 家。同时补上显式清单路径缺失的 ST/退市过滤。

## 格力电器事件时效性修复（第 6 轮：用户提交《格力电器评分修正模块_成长偿债营运.py》）

### 用户方案的"旧值"对、"综合分算法"错

方案列的五维旧值（盈利 86.8 / 成长 63.5 / 现金流 89.4 / 偿债 57.6 / 估值 83.2）
与系统 `dim_scores` **逐位一致**，但它按**等权 1/5** 算出"旧综合 76.1"，真实值 **59.7**。

真实链路（`engine.py:281-304` + `431`）：
```
MODULE_WEIGHTS = {profitability 0.2, growth 0.16, solvency 0.16, cashflow 0.32, valuation 0.16}
加权平均 = 78.66（E 档打折未触发，最低的偿债 57.6 > E_GRADE_SCORE=40）
risk 51.0 < RISK_THRESHOLD=60 → 乘数 (1 - 0.25×(60-51)/60) = 0.9625 → 75.7
观察级风险 2 个 → composite -= 8×2 = 16 → 59.7 ✓
```
**教训：用户给的"旧综合分"必须独立复算，别采信。**

### 真实缺陷（1 个）：风险事件"已结束却仍按新增扣分"

2 个观察事件原文（`_diag_bank.py` 末尾 `〔观察〕` 行）：
1. 【实控人/大股东减持】2026-06-22 关于大股东**减持计划期限届满**暨减持结果的公告
2. 【大股东高比例质押】珠海明骏单笔质押占所持股份 67.6%

第 1 条是**减持已到期结束**的公告，但 `RISK_RELEASE_KEYWORDS` 里只有「减持计划届满」，
`"减持计划届满" in "减持计划期限届满暨减持结果"` = **False**（少「期限」两字），
释放失败 → 白扣 8 分。

**修法（治本）**：`major_risk_events.py` 加 `_is_release_title()`，改用语义组合规则
（同时含「减持」与「届满/到期」），覆盖「减持计划期限届满 / 减持期限届满 /
减持计划时间届满 / 减持计划届满」等全部变体；同时保证不误释放「拟减持」与
「限售期届满」（后者不含「减持」）。

### 外部信源交叉验证（关键）

起初怀疑 797.19 亿短期借款是数据错误，检索后确认**完全属实**（占总资产 19.97%）：
- 「存贷双高」是市场公认问题："手握巨额现金，却仍在加杠杆借短期债"
- 反面证据（方案未提）：营收三连降（2050→1900→1711 亿）、**合同负债从 152 亿腰斩到 84.74 亿**、
  经营现金流 188.09 亿**同比 -33.6%**（净利降幅的 4 倍）、研发 -19.01%、**中期不分红**、
  扣非净利 -8.89%
- 主营收入 852.56 亿（-2.56%），非主业 -57.87% —— 方案只引用后者证明"主动收缩"，
  但空调主业（占八成）确实在收缩，行业零售额 -13.8%

**结论：格力 59.7 分并未低估，反而偏宽松。** 修复后 70.7（B-）对一个
"低估值+高盈利+零成长+控股股东质押 67.6%"的标的属合理。
